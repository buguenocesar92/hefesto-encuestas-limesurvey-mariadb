# Despliegue y Coolify
1. Usar proyecto, prefijo de volúmenes y subdominio separados por cliente. Generar .env; no subirlo a Git ni al contexto de build. Cambiar las claves iniciales dentro de LimeSurvey después de iniciar sesión. ADMIN_PASSWORD debe conservar un valor no vacío por exigencia de la imagen; cambiarlo en env no cambia la clave de un administrador existente.
2. Esperar la instalación y revisar `docker compose logs --tail 100 app` y `docker compose ps`. El entrypoint upstream ejecuta updatedb y, si falla, intenta instalar; no asumir que cualquier error significa base vacía. Ante errores detener app, revisar conectividad/esquema y no reiniciar repetidamente.
3. Crear un administrador nominal y cuentas limitadas para editores/analistas. Configurar español, marca, plantillas y zona horaria según el cliente. Probar permisos con dos usuarios. No activar una encuesta con datos reales hasta completar su vista previa.
4. Para producción usar solo compose.yaml: `docker compose -f compose.yaml up -d --build --force-recreate app`. Esto retira localhost:8088 y cambia hostInfo al dominio HTTPS. No usar el override de bootstrap en Coolify.
5. En Coolify cargar el directorio como recurso Compose con build Dockerfile; ingresar variables de .env y asociar HTTPS al servicio app en puerto interno 8080. Preservar nombres de volúmenes si se migra el recurso en el mismo VPS; detener primero el anterior. No mantener dos apps sobre la misma base. Usar los scripts en el contexto Compose del recurso real.
6. El proxy debe conservar Host y X-Forwarded-Proto, descartar cabeceras aportadas por clientes y controlar el dominio permitido. Verificar enlaces, cookies, formularios y redirecciones HTTPS; no abrir el puerto de MariaDB. La imagen comunitaria confía X-Real-IP de redes privadas: exponer app solo mediante el proxy controlado y no compartir su red con contenedores no confiables.
7. Envío PHP mail deshabilitado en php.ini. Para invitaciones/recuperación configurar SMTP autenticado desde ajustes nativos, probar un destinatario autorizado y controlar rebotes/límites. No hay envíos programados en este kit.
8. Configurar límites de cuerpo del proxy acordes con PHP (20 MB por archivo, 24 MB por petición). Mantener carga de adjuntos desactivada en encuestas que no la requieren.
9. Ejecutar docs/aceptacion.md, respaldar y documentar responsable de operación. Se recomienda empezar con una encuesta privada piloto.

No editar config.php manualmente: usar ops/configure.php para cambios gestionados. Aplicar marcas/temas en upload mediante la aplicación, sin borrar atribuciones requeridas. El volumen config persiste archivos de la versión: antes de actualizar comparar con application/config del nuevo release e incorporar cambios upstream conservando security.php y personalizaciones. No usar actualización web para reemplazar código dentro de un contenedor efímero.
